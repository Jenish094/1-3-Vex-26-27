\chapter{Codebase Summary }
\hypertarget{index}{}\label{index}\index{Codebase Summary@{Codebase Summary}}
Welcome to the codebase for 41103C 1/\+3\textquotesingle{}s 2026-\/2027 VEX V5 robot. This page is a map of the robot software: what the brain runs, how the controllers are assigned, what hardware the code talks to, and where the main pieces live.

The source is available for portfolio, judging, and educational review on \href{https://github.com/Jenish094/1-3-Vex-26-27}{\texttt{Git\+Hub}}. Use the navigation panel to browse the documented headers, types, and implementation files.\hypertarget{index_autotoc_md9}{}\doxysubsection{\texorpdfstring{At a glance}{At a glance}}\label{index_autotoc_md9}
The V5 brain runs the PROS firmware. The main program initializes hardware and the on-\/brain autonomous selector, then switches between competition callbacks for autonomous, driver control, and disabled states. LVGL is used by the brain-\/side display and dashboard interface. Odometry, driver input, mechanism controls, and autonomous routines are implemented in the project source rather than being separate libraries.

\hypertarget{index_autotoc_md10}{}\doxysubsection{\texorpdfstring{Robot and brain}{Robot and brain}}\label{index_autotoc_md10}
The robot uses a four-\/motor drivetrain, a motor-\/driven intake, a two-\/motor cascade, and separate score/\+wrist mechanisms. A pneumatic brake is also available to the driver controls. The hardware declarations and device initialisation are in {\ttfamily \doxylink{robot__hardware_8hpp_source}{include/\+robot\+\_\+hardware.\+hpp}} and {\ttfamily src/\+robot\+\_\+hardware.\+cpp}.

The brain runs PROS. During initialisation, the program initialises the devices, resets odometry, starts the recorder task, and presents an autonomous selector. During driver control, it reads the primary controller and updates the cascade automation. During autonomous, it runs the selected callback. The dashboard uses LVGL-\/based code; the current autonomous selection is the main brain-\/screen workflow exposed from {\ttfamily src/\+main.\+cpp}.\hypertarget{index_autotoc_md11}{}\doxysubsection{\texorpdfstring{Controllers}{Controllers}}\label{index_autotoc_md11}

The controller screens provide quick status: the primary screen displays cascade encoder position, and the partner screen shows the selected goal and scoring modes. The detailed input loop and display updates are in {\ttfamily src/\+controls.\+cpp} and {\ttfamily src/\+functions.\+cpp}.\hypertarget{index_autotoc_md14}{}\doxysubsection{\texorpdfstring{Sensors and hardware feedback}{Sensors and hardware feedback}}\label{index_autotoc_md14}

\begin{DoxyItemize}
\item {\bfseries{Two passive tracking-\/wheel rotation sensors:}} vertical and horizontal wheel travel used by odometry.
\item {\bfseries{Inertial sensor:}} heading change used with tracking-\/wheel movement to estimate field pose.
\item {\bfseries{Cascade rotation sensor:}} cascade position feedback for preset-\/height automation and the primary controller display.
\item {\bfseries{Optical sensor:}} initialized in the hardware layer; color-\/detection logic is present, but its activation path is not currently connected to a driver input.
\item {\bfseries{AI Vision port:}} Allows the robot to align with the goal\textquotesingle{}s April\+Tags when required ~\newline

\item {\bfseries{Motor encoders:}} mechanism motor position is available for local actions such as the wrist macro. Drivetrain motor encoders are not used by field odometry.
\end{DoxyItemize}

Odometry converts tracking-\/wheel rotation into inches and combines that motion with IMU heading changes to update X, Y, and heading. The \doxysectlink{autonomous_recording}{Autonomous Recording System}{0} page explains how pose samples are recorded and converted into a path-\/following routine.\hypertarget{index_autotoc_md15}{}\doxysubsection{\texorpdfstring{Autonomous}{Autonomous}}\label{index_autotoc_md15}
The brain\textquotesingle{}s selector currently offers 20-\/point, 30-\/point, and 40-\/point routines for the left and right sides, a Skills routine, and disabled. The longer routines build on shorter routines and combine robot movement with cascade, intake, wrist, and roller actions. The Skills routine currently calls the loading routine.

The code also includes a loading routine and a recorded-\/routine placeholder. The recorded routine is not currently enabled in the selector and its function body is empty. The recording converter can generate a path-\/following implementation, but that generated source still needs to be integrated into the robot project and selector.

Movement helpers use odometry for distance and heading control. The route follower tracks a list of field coordinates using the live pose estimate. Autonomous declarations are in {\ttfamily \doxylink{auto_8h_source}{include/\+auto.\+h}}; routine implementations and selector setup are in {\ttfamily src/\+auto.\+cpp} and {\ttfamily src/\+main.\+cpp}.\hypertarget{index_autotoc_md16}{}\doxysubsection{\texorpdfstring{Quality-\/of-\/life features}{Quality-\/of-\/life features}}\label{index_autotoc_md16}

\begin{DoxyItemize}
\item {\bfseries{Cascade presets:}} the partner controller selects goal type, scoring mode, and a level up to 10. The controller loop uses the cascade rotation sensor to move toward the corresponding target.
\item {\bfseries{Manual override and stop controls:}} the primary controller can take manual cascade control; partner controls can cancel automation or reset its sensor position.
\item {\bfseries{Pin-\/grab macro:}} a staged sequence coordinates cascade travel, wrist movement, and the score roller, with a timeout on movement stages.
\item {\bfseries{Controller status screens:}} mechanism position and selected cascade modes are visible without connecting a laptop.
\item {\bfseries{Autonomous selector:}} routines are selected on the brain rather than by editing the selected callback at runtime.
\item {\bfseries{Recording-\/to-\/path tool:}} the separate converter reduces recorded pose samples and emits C++ waypoint-\/following code. See \doxysectlink{autonomous_recording}{Autonomous Recording System}{0}.
\end{DoxyItemize}\hypertarget{index_autotoc_md17}{}\doxysubsection{\texorpdfstring{Codebase layout}{Codebase layout}}\label{index_autotoc_md17}

\hypertarget{index_autotoc_md18}{}\doxysubsection{\texorpdfstring{Libraries}{Libraries}}\label{index_autotoc_md18}
The robot project uses two external robotics/\+\+UI libraries:


\begin{DoxyItemize}
\item {\bfseries{PROS:}} V5 runtime, competition lifecycle, motor and sensor APIs, tasks, and controller access.
\item {\bfseries{LVGL:}} graphics and user-\/interface primitives used by the brain display and dashboard code.
\item {\bfseries{Doxygen-\/\+Awesome-\/\+CSS:}} For our doxygen documentation theme
\end{DoxyItemize}
